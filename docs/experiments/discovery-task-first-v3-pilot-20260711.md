# Discovery Agent v3 首轮任务优先小试验

## 1. 实验目的

本轮不是正式替代实验，而是验证新版 benchmark 链路，并观察 Agent 在真实任务、三种表达方式下是否出现可解释的质量提升。

只使用开发集中的两类任务：跨实验室保留时间预测与人类 HCD 碎片强度预测。每类任务包含明确、普通、模糊三种表达，共 6 题。Workflow 使用当前固定流程；Agent 使用 `max_quality` 安全硬上限内的自主预算。每题运行一次。

## 2. 实验版本与产物

- 日期：2026-07-11 至 2026-07-12
- Agent 模型：`deepseek-v4-pro`
- 判卷模型：`deepseek-v4-pro`
- 判卷来源：`provisional_same_family`
- 正式替代证据：否
- 本地产物：`runs/benchmarks/discovery-task-first-v3-pilot-20260711`
- 运行实例：12 个，6 个 Workflow + 6 个 Agent
- 盲评候选：270 个，其中中立高召回候选 240 个

本轮运行目录使用 `.agent_keep` 防止网页服务的结果清理器删除。自动判卷支持候选级断点续判。

## 3. 自动判卷情况

- 总投票数：855
- 两票一致后结束：165 个候选
- 分歧后扩展到五票：105 个候选
- 高置信度：13 个
- 中置信度：201 个
- 低置信度：56 个

低置信度约占 21%。报告同时检查了包含全部候选和排除低置信度候选后的结果。

## 4. 总体结果

- Agent：3 胜、3 平、0 负
- Agent 胜率：50%
- 平均质量差：`+0.038`
- 普通/模糊表达平均质量差：`+0.058`
- Agent / Workflow 仓库请求比：`1.378`
- Agent / Workflow 耗时比：`2.835`
- 新增硬约束错误：0
- 平均文件包差：0

当前结果没有通过替代门槛：评分来自与 Agent 相同的模型系列；只有 6 个单次配对；50% 胜率低于初始 65% 目标；平均质量提升和普通/模糊表达提升也低于当前预设门槛。

## 5. 逐题结果

| 任务 | 表达 | 结果 | 质量差 | Workflow/Agent 请求 | Workflow/Agent 耗时（秒） | 主要原因 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| 保留时间 | 明确 | 平 | -0.006 | 48 / 74 | 110 / 269 | 两边最终项目均没有 2 分以上候选 |
| 保留时间 | 普通 | 平 | +0.007 | 45 / 67 | 92 / 277 | Agent 增加搜索，但没有换来相关性提升 |
| 保留时间 | 模糊 | 平 | -0.009 | 45 / 72 | 90 / 246 | Agent 任务就绪度和证据完整度反而略低 |
| 碎片强度 | 明确 | Agent 胜 | +0.003 | 48 / 78 | 85 / 295 | Workflow 有 1 个硬约束错误，Agent 没有 |
| 碎片强度 | 普通 | Agent 胜 | +0.012 | 47 / 37 | 94 / 226 | Workflow 有 1 个硬约束错误，Agent 没有 |
| 碎片强度 | 模糊 | Agent 胜 | +0.222 | 45 / 55 | 82 / 255 | Agent 找到 3 个 ProteomeTools 相关 2 分项目 |

本轮不能把“3 胜”简单解释为三次明显质量提升。前两次碎片强度胜利主要来自硬约束门槛；真正由项目相关性拉开的胜利只有模糊碎片强度题。

## 6. 排除低置信度后的敏感性检查

排除低置信度候选后，六题方向仍为 3 胜、3 平、0 负。

- 保留时间三题仍全部为平局。
- 碎片强度明确和普通题仍因硬约束错误差异判 Agent 胜。
- 模糊碎片强度题质量差由 `+0.222` 降到 `+0.125`，仍判 Agent 胜。

因此本轮胜负方向没有由低置信度样本单独决定。但模糊碎片题中 Agent 选择的三个 2 分项目有两个是低置信度，优势大小仍需独立模型或人工复核。

## 7. 本轮暴露的真实问题

### 7.1 文件选择是两套系统的共同短板

所有 12 个运行都主要选择了原始谱图：文件包完整度均为 `0.5`，搜索结果文件数为 0，元数据文件数为 0，没有形成原始谱图 + 搜索结果 + 元数据的任务就绪文件包。

这意味着当前 Discovery 更接近“选择原始数据”，还没有完成用户要求的 AI-ready 清单。下一轮应优先修复选择工具和最终清单策略，而不是只继续调项目搜索提示词。

### 7.2 Agent 没有改善保留时间任务

在三种表达中，Agent 增加了请求量和耗时，但没有选择任何 2 分以上项目。中立候选池找到了多批 2 分候选，说明问题不是 PRIDE 完全没有可用项目，而是 Agent 的搜索、检查或最终选择没有把这些候选带入答案。

下一轮需要检查 Agent 是否把 LC 梯度、肽段鉴定和保留时间证据作为项目检查目标，是否过度追逐近期的一般 DDA 项目，以及是否在候选池中找到合适项目却因文件选择或最终排序丢失。

### 7.3 Agent 在模糊碎片强度需求中体现了设计价值

Agent 选择了 `PXD021013`、`PXD010595` 和 `PXD004732` 等 ProteomeTools 相关项目，而 Workflow 没有选择这些项目。这是本轮最符合“Agent 在模糊需求下主动理解任务并调整搜索”的正面案例。

但其中两个项目评分为低置信度，仍需独立评价来源确认优势大小。

### 7.4 自动评价仍需校准

同模型盲评能够区分明显无关、一般相关和较强候选，但有些中立池 2 分项目从标题看并不直接针对保留时间或碎片强度。判卷模型可能把“有原始谱图和搜索结果的一般 DDA 项目”视为可用于训练。

下一版评价应拆成三个可审计维度：

1. 生物学和实验范围是否符合需求。
2. 是否具有目标 AI 任务真正需要的标签与元数据。
3. 项目文件是否能组成可执行的数据包。

拆分后再合成 0–3 相关性分，减少不同判卷回合对“可用”的理解差异。

## 8. 基础设施问题与修复

本轮首次运行暴露了两个问题：网页服务默认每 30 分钟清理 `runs` 下未保护目录，曾删除首次实验产物；首版自动判卷整池完成后才写文件，长任务中断会丢失全部已完成票。

已完成修复：

- benchmark 启动时自动在实验目录和 `runs/benchmarks` 写 `.agent_keep`。
- 自动判卷每完成一个候选即写入带指纹的 JSONL 检查点。
- 指纹包含候选可见事实、模型、评分来源和 rubric 版本。
- 实际中止后成功从 236 个已完成候选恢复，只补判剩余 34 个。

## 9. 下一轮优化顺序

1. 修复最终文件包选择，要求原始谱图、搜索结果和元数据按任务组合，而不是只选原始文件。
2. 为保留时间任务增加证据目标和最终选择检查，重点检查 LC 梯度、鉴定结果和 RT 标签可生成性。
3. 将自动判卷拆成任务相关性、标签/元数据、文件包三个维度。
4. 在评价页面展示机器投票、置信度和低置信度过滤结果，同时保留人工评分。
5. 对同一 6 题再运行第二次，检查修复是否稳定提升。
6. 通过开发集校准后再运行冻结保留集；当前不得使用保留集结果调 Agent。

## 10. 当前结论

> Agent 在碎片强度任务，尤其模糊表达下，出现了有意义且对低置信度过滤稳定的初步优势；但它没有改善保留时间任务，两套系统也都没有产出完整文件包。因此 Agent 尚未达到替代 Workflow 的条件。

这是一项内部临时结论，不是人工或独立模型验证结论。
