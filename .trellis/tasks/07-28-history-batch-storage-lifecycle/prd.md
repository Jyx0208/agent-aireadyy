# 历史任务与批次存储生命周期

## Goal

让用户能够复用已经完成的数据发现结果、按真实增量批次把文件送入批量处理，并在磁盘紧张时安全释放历史任务和批量处理源文件占用的空间，避免重复检索和不可控的磁盘增长。

## Background

数据发现采用开放上限，每形成 500 个新的可交付文件就产生一个冻结批次，最后一个尾批次可以少于 500 个。同一文件不得跨批次重复，同一 PRIDE 项目的不同文件可以分布在不同批次。当前全局批量交接读取累计清单，历史入口不能重新打开发现结果或安全删除任务，批量下载与转换资产也没有用户可控的生命周期，因而存在重复处理和磁盘不可控增长的风险。

## Requirements

### R1 — 精确的 500 文件增量批次

- 每个已交付批次只包含该批次新增且未在先前批次发布过的文件。
- 前端允许直接将指定批次送入批量处理，不读取累计清单。
- 批次交接保留文件对应的仓库、项目编号、文件名、下载地址和采集模式等结构化上下文。
- 批次界面清楚显示批次编号、文件数量、发布时间和处理状态。

### R2 — 历史任务复用

- 历史任务展示发现条件、状态、关键计数、创建/完成时间、磁盘占用和结果是否仍可复用。
- 用户可以重新打开已存在的发现结果、项目审查过程和已发布文件批次，无须重新运行相同检索。
- 是否复用由用户在历史任务中主动决定；系统不识别或拦截所谓“相同任务”，也不在新任务启动前自动匹配历史结果。
- 进行中任务不得被误当作已完成缓存；失败或不完整任务必须明确标注可恢复范围。

### R3 — 历史任务删除与空间回收

- 仅允许删除已完成、已失败或已停止的任务；运行中的任务必须先停止。
- 删除前显示删除范围和预计释放空间，并要求明确确认。
- 删除发现任务默认只删除发现任务；界面可额外勾选“同时删除关联批量任务”，默认不勾选，并分别显示两部分预计释放空间。
- 删除只能作用于系统管理的任务目录，不得删除目录外文件、用户原始文件或共享缓存。
- 删除后记录实际释放空间及失败项；列表状态立即同步。
- 发现任务与由它创建的批量任务之间的关系必须可见，避免用户误以为删除一方会自动删除另一方。

### R4 — 批量处理完成后清理源文件

- 批量处理增加“处理完成后删除本地源文件”选项，默认关闭。
- 选项只作用于当前新建批量任务，不追溯修改既有任务。
- 开启后，每个文件成功完成并且结果、清单与审计已经落盘时立即清理该文件的受控资产，不等待整个批次结束。
- 只清理批量任务目录内可重建的下载文件和转换中间文件；保留参数、日志、审计、清单以及最终结果。
- 不删除用户输入的本地原文件、系统目录外文件或多个任务共享的缓存。
- 清理失败不得掩盖处理成功结果；界面需显示清理状态、失败原因和实际释放空间。
- 失败、需复核和取消项目保留源文件以便排错。

## Acceptance Criteria

- [ ] AC1：选择任意已发布批次送入批量处理时，输入文件数等于该批次文件数，且不含更早批次的文件。
- [ ] AC2：一个完整的 500 文件批次传入 500 个唯一文件；尾批次按实际数量传入。
- [ ] AC3：历史任务页能打开一项已完成发现任务，并恢复其策略、进度、审查结论和批次，而不触发网络检索。
- [ ] AC4：启动新发现任务时不进行历史相似性匹配；用户可从历史页主动打开已有结果。
- [ ] AC5：历史列表显示任务独占磁盘占用；运行中任务的删除操作不可用。
- [ ] AC6：确认删除终态任务后，只移除受管理任务目录并报告实际释放字节数；越界路径会被拒绝。
- [ ] AC7：批量处理清理选项默认关闭，关闭时现有文件生命周期保持不变。
- [ ] AC8：清理选项开启后，成功处理项目的任务内下载/转换文件被删除，结果、参数、清单、日志和审计仍可打开。
- [ ] AC9：处理失败时源文件被保留；清理失败会单独显示且不把成功处理改为失败。
- [ ] AC10：后端测试、前端测试、类型检查和关键浏览器流程验证通过。

## Out of Scope

- 自动删除用户工作区中的原始本地文件。
- 在没有用户确认的情况下按磁盘阈值自动淘汰历史任务。
- 跨服务器或跨安装实例共享历史任务。
- 把所有历史数据迁移到外部对象存储。

## Technical Notes

- 数据发现任务已经分别持久化任务 JSON、运行目录和 `project_history.json` 索引；`GET /api/history` 已能合并普通任务、批量任务与发现任务，但前端目前故意不为 discovery 渲染“打开”按钮。
- 发现任务运行目录中的 `dataset_request.json` 可用于恢复并展示当时的策略；本任务不使用它进行历史相似性匹配。
- 已发布文件批次位于 `verified_batches/batch_NNN/`；当前批次下载接口只提供 JSON manifest，尚无“取本批次批量输入和结构化 input_records”的交接接口。
- 批量任务都位于 `runs/batches/<batch_id>/`，单项位于其 `items/` 子目录；下载和转换资产位于单项的 `assets/downloads/` 与 `assets/prepared/`，可以用现有路径越界校验机制限定清理范围。
- 批量任务已经持久化 manifest，并在历史记录里计算整个任务目录的 `size_bytes`。目前没有删除 API，也没有批量任务与来源 discovery/batch index 的稳定关联字段。
